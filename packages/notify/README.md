# dsh-enhance-notify（回复提醒）

一轮回复结束时响一下：**播放一段提示音**；**窗口不在前台时**再弹一条系统通知。

它属于 [dsh-enhance](../../README.md) 这个 bundle，是第三个组件，和「自动化任务」「会话解压」各管各的：
关掉它，另两个照常工作。

中文 | [English](./README.en.md)

---

## 它解决什么问题

dsh 自己不会告诉你「这一轮说完了」。人切到别的窗口干活，回来时只能盯着窗口猜；
桌面端更糟 —— 窗口最小化以后什么也看不见。

这个组件补上这个提示：**一轮回复结束时播放一段提示音**；**窗口不在前台时**（切到别的应用、
最小化、或者浏览器切了标签）**再弹一条系统通知**，在 Windows 上就是操作中心里那条 toast，
点它能把窗口拉回前台。

## 怎么用

设置放在**插件详情页**里，不占输入框下方的位置：

1. 打开插件页 → 「已安装插件」→ 点进「DSH 增强」；
2. 在「包含的组件」里找到「回复提醒」，点它那一行的**「配置」**；
3. 出来的就是这个组件的设置页：

- **提示音**：一轮结束时播放（开关）；
- **提示音音色**：四种音色任选其一 —— 清脆（两个泛音的短叮）、铃声（基频加三个泛音）、
  短促（两下低脉冲）、渐强（三个音上行）。四段全是 Web Audio 现场合成的，不带任何音频文件；
- **系统通知**：窗口不在前台时弹出（开关，浏览器的 Notification API，Windows 上就是原生 toast）；
- **试听音色**：当场听一遍当前选的音色。

设置里的开关与音色记在浏览器的 `localStorage` 里（键 `dsh.enhance.notify`），换台电脑要重新开。

「配置」这个入口是宿主给组件留的位置（`plugins.row.config`），键是
`<bundle 包名>#<组件 id>`。它只在这个组件启用时出现，组件关掉后连同它的设置页一起消失。

## 它怎么知道「回复结束了」

宿主在 **Agent 的运行状态变化**时会转发一个 `api-session/status` 事件（`sessionId, running`）。
组件自己记着哪些会话正在跑：**`true` 记下，`false` 且之前在跑 ⇒ 一轮结束**。
没有前置 `true` 的 `false`（连接时的初始状态、Agent 被回收）不算一次结束。

子智能体自己的那一轮不算数 —— 用户等的是当前会话的回复。

## 它由哪些部分组成

| 部位 | 职责 |
| --- | --- |
| `src/client/index.js` | 订阅 `api-session/status`，判断一轮结束，注册配置页 |
| `src/client/tones.js` | 四种音色的音高与时值表 |
| `src/client/chime.js` | Web Audio 合成与播放（泛音、逐音衰减） |
| `src/client/system-notification.js` | 系统通知（Notification API）与权限提示 |
| `src/client/settings.js` | `localStorage` 里的偏好读写（开关 + 音色） |
| `src/client/components/settings-page.js` | 插件详情页里的设置页（自绘开关与音色下拉） |
| `src/client/styles.js` | 这个页面自己的皮肤，只用 `--dsw-*` 主题 token |
| `src/index.js` | 宿主半（空入口，浏览器代码不能进 Node） |

几个关键决定：

- **提示音全部现场合成**：不发一个音频文件，四段音色是 `tones.js` 里的音高表 + `chime.js` 里的
  振荡器与包络。包体不膨胀，音色随便加。
- **音色切换即时试听**：选中的那一段当场响一次，记住的是**被选中的**那个音色，
  一轮结束时播的也是它。
- **设置存浏览器而不是 profile 配置**：提示音是「这一台机器的习惯」，不是部署的事实；
  存 `localStorage` 也就绕开了 profile 配置需要的 schema 依赖。
- **客户端半不 import 任何 Harness Client 包**：开关、下拉菜单都是自己画的，
  只用宿主主题的 token 与 sprite symbol，所以不会和 dsh 版本的前端包打架。
- **系统通知只在窗口失焦时发**：正看着窗口时再弹 toast 是噪音，不是信号。

## 依赖的宿主契约

- `api-session/status` 这个状态事件（`sessionId, running`）；
- `plugins.row.config` 这个配置页位置。

宿主改了这两样里的任何一个，这个组件都要跟着改。

## 已知限制

- **首次播放需要一次用户交互**：浏览器的自动播放策略要求页面先被点过一下。组件在第一次
  指针/按键事件时就把音频上下文解锁，所以正常用过一轮之后都能响。
- **通知权限由浏览器管**：第一次弹通知时浏览器会问；被拒了组件会提示去站点设置里放行。
- **系统通知只在窗口失焦时发**：正看着窗口时再弹 toast 是噪音，不是信号。
- **只监听状态事件**：所以它知道「这一轮结束了」，但不知道「这一轮说了什么」——
  通知正文是会话标题，不带内容。

## 构建与测试

```sh
cd packages/notify
npm install
npm run bundle          # 产物在 lib/（不进版本库）
```

测试在仓库根目录：

```sh
node --test tests/notify-behavior.mjs
```

覆盖：配置页注册（`plugins.row.config`，键是 `<bundle>#<组件 id>`）、不碰 composer dock、
配置页画出两个开关、**运行状态边沿才算一轮结束**、子智能体那一轮不算、
**窗口失焦才发系统通知**、两个开关能关掉声音与通知、开关落在 `localStorage` 里、
**四种音色都在菜单里**、**选中的音色被记住**、**播放的就是选中的那个音色**。
